# Датасет

Документ описывает данные, на которых обучена модель TomatoCare: состав, структуру, подготовку и известные ограничения.

## Общие сведения

| Параметр | Значение |
|---|---|
| Культура | томат |
| Задача | классификация фотографии листа |
| Число классов | 10 (9 заболеваний + здоровый лист) |
| Всего изображений | 22 524 |
| Источник | https://www.kaggle.com/datasets/ashishmotwani/tomato |

## Классы

Индексы классов определяются алфавитным порядком названий папок (так их нумерует `torchvision.datasets.ImageFolder`). Этот же порядок записан в `classes.json` и должен совпадать в `ml/` и в `app/src/main/assets/`.

| Индекс | Класс | Состояние |
|---|---|---|
| 0 | `Bacterial_spot` | Бактериальная пятнистость |
| 1 | `Early_blight` | Ранняя пятнистость (альтернариоз) |
| 2 | `Late_blight` | Фитофтороз |
| 3 | `Leaf_Mold` | Кладоспориоз |
| 4 | `Septoria_leaf_spot` | Септориоз |
| 5 | `Spider_mites Two-spotted_spider_mite` | Паутинный клещ |
| 6 | `Target_Spot` | Мишеневидная пятнистость |
| 7 | `Tomato_Yellow_Leaf_Curl_Virus` | Вирус жёлтой курчавости листьев |
| 8 | `Tomato_mosaic_virus` | Вирус мозаики томата |
| 9 | `healthy` | Здоровый лист |

## Структура и разбиение

Данные разделены на три непересекающиеся выборки и хранятся в формате «одна папка — один класс»:

```
train/
  Bacterial_spot/
  Early_blight/
  ...
valid/
  ...
test/
  ...
```

| Выборка | Изображений | Доля | Назначение |
|---|---|---|---|
| `train` | 15 762 | ≈ 70 % | обучение |
| `valid` | 3 373 | ≈ 15 % | выбор лучшей эпохи |
| `test` | 3 389 | ≈ 15 % | итоговая оценка, используется один раз после обучения |

Количество изображений по классам в тестовой выборке:

| Класс | Изображений |
|---|---|
| `Bacterial_spot` | 425 |
| `Early_blight` | 336 |
| `Late_blight` | 454 |
| `Leaf_Mold` | 381 |
| `Septoria_leaf_spot` | 433 |
| `Spider_mites Two-spotted_spider_mite` | 263 |
| `Target_Spot` | 275 |
| `Tomato_Yellow_Leaf_Curl_Virus` | 307 |
| `Tomato_mosaic_virus` | 324 |

Классы не идеально сбалансированы: самый крупный (`Late_blight`) примерно в 2,4 раза больше самого малочисленного (`healthy`). Для текущей модели это не критично (recall у `healthy` — 1,00), но учитывается при анализе ошибок.

## Подготовка

1. **Проверка классов.** Названия папок в `train`, `valid` и `test` совпадают; скрипт обучения останавливается с ошибкой, если списки классов расходятся.
2. **Удаление явных дубликатов.** Скрипт `remove_duplicates.py` считает MD5-хэш каждого файла в `train/`, показывает найденные пары «удалить / оставить» и удаляет дубликаты только после подтверждения (`y`). Найдено и удалено дубликатов: [N].
3. **Разбиение на выборки.** Разбиение выполнено заранее, до обучения; файлы `valid` и `test` в обучении не участвуют.

## Обучающие преобразования

Только для `train` применяется аугментация: случайное горизонтальное отражение (p = 0,5), поворот до ±15°, изменение яркости, контраста и насыщенности (±20 %). Для `valid` и `test` выполняются только приведение к размеру 224 × 224 и нормализация.

## Известные ограничения

- Дубликаты искались только внутри `train` и только по точному совпадению файла. Проверки на пересечения между `train`, `valid` и `test`, а также на почти одинаковые изображения (например, один и тот же лист, снятый с разных ракурсов) не проводилось. Если такие пары есть, итоговая точность на `test` завышена. Для этого предусмотрена независимая проверка на фотографиях из другого источника (этап 14).
- Изображения датасета сняты в относительно однородных условиях. На реальных снимках с произвольным фоном и освещением качество может быть ниже.
- Сами изображения в репозиторий не включаются.

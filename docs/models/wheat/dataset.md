# Датасет

Документ описывает данные, на которых обучена модель пшеницы TomatoCare: состав, структуру, подготовку и известные ограничения.

## Общие сведения

| Параметр | Значение |
|---|---|
| Культура | пшеница |
| Задача | классификация фотографии листа |
| Число классов | 4 (3 заболевания + здоровый лист) |
| Всего изображений | 7 984 |
| Источник | Kaggle (несколько датасетов, в том числе PlantVillage: https://www.kaggle.com/datasets/abdallahalidev/plantvillage-dataset) |

## Классы

Индексы классов определяются алфавитным порядком названий папок (так их нумерует `torchvision.datasets.ImageFolder`). Этот же порядок записан в `classes.json`.

| Индекс | Класс | Состояние |
|---|---|---|
| 0 | `brown_rust` | Бурая ржавчина |
| 1 | `healthy` | Здоровый лист |
| 2 | `mildew` | милдью |
| 3 | `yellow_rust` | Желтая ржавчина |

## Структура и разбиение

Данные разделены на три непересекающиеся выборки и хранятся в формате «одна папка — один класс»:

```
train/
  Brown_rust/
  Healthy/
  ...
valid/
  ...
test/
  ...
```

| Выборка | Изображений | Доля | Назначение |
|---|---|---|---|
| `train` | 5 599 | ≈ 70 % | обучение |
| `valid` | 1 186 | ≈ 15 % | выбор лучшей эпохи по val_loss |
| `test` | 1 198 | ≈ 15 % | итоговая оценка, используется один раз после обучения |

Количество изображений по классам:

| Класс | train | valid | test | Всего |
|---|---|---|---|---|
| `Brown_rust` | 1 776 | 380 | 382 | 2 538 |
| `Healthy` | 1 276 | 262 | 269 | 1 807 |
| `Mildew` | 471 | 100 | 102 | 673 |
| `Yellow_rust` | 2 074 | 444 | 445 | 2 963 |

Классы не идеально сбалансированы: самый крупный (`yellow_rust`) примерно в 4,4 раза больше самого малочисленного (`mildew`). Из-за чего оценка по классу `mildew` менее устойчива.

## Подготовка

1. **Приведение классов.** Названия классов из разных источников приведены к единым (`brown_rust`, `healthy`, `mildew`,  `yellow_rust`). Папка «Insects damage» (повреждения насекомыми) из одного из датасетов в выборку не включена, так как не входит в набор классов.
2. **Удаление дубликатов.** Скрипт dubles.py считает MD5-хэш каждого файла, показывает найденные пары «удалить / оставить» и удаляет дубликаты только после подтверждения (y).
3. **Разбиение на выборки.** Стратифицированное разбиение 70/15/15 выполнено после удаления дубликатов; файлы `valid` и `test` в обучении не участвуют.

## Обучающие преобразования

Только для `train` применяется аугментация: случайное горизонтальное отражение (p = 0,5), поворот до ±10°, изменение яркости, контраста и насыщенности (±15 %). Для `valid` и `test` выполняются только приведение к размеру 224 × 224 и нормализация.

## Известные ограничения

- Почти одинаковые изображения ищутся только по хэшу (dHash): повёрнутые или отражённые копии и разные снимки одного и того же растения скрипт не находит. Если такие пары остались, итоговая точность на `test` немного завышена. Для независимой оценки модель проверена на фотографиях из интернета (см. `model.md`).
- В исходных датасетах встречаются изображения, подписанные разными классами (удалено 6 таких файлов); не исключены и другие ошибки разметки, особенно между `brown_rust` и `yellow_rust`.
- Изображения датасета в основном сняты крупным планом листа. На дальних планах и в сложных сценах качество модели заметно ниже (см. `model.md`).
- Сходство между двумя классами(`brown_rust` и `yellow_rust`) порождает ошибки в их классификации.
- Сами изображения в репозиторий не включаются.

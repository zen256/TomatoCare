## Цель и выбранные решения

Цель работы: создать модуль распознавания заболеваний одной сельскохозяйственной культуры по фотографии листа и встроить его в пользовательскую программу.

| Вопрос | Решение |
|---|---|
| Культура | томат |
| Что распознаётся | 9 заболеваний и здоровый лист (10 классов) |
| Тип задачи | классификация изображения целиком (один лист — один класс) |
| Платформа | Android-приложение |
| Где выполняется анализ | на устройстве, без сервера |
| Модель | EfficientNet-B0, предобученная на ImageNet |
| Формат модели в приложении | ONNX |
| Технологии приложения | Kotlin, Jetpack Compose, ONNX Runtime |

## Этап 1. Постановка задачи

**Требование:** разобраться в задаче, составить список вопросов, сформировать основной пользовательский сценарий, обсудить минимально рабочую версию.

**Что сделано.** Составлен список вопросов, ответы на которые определили дальнейшую работу:

| Вопрос | Ответ |
|---|---|
| Какую культуру выбрать? | Томат: много открытых размеченных данных, хорошо различимые симптомы на листе |
| Какие состояния распознавать? | Девять наиболее распространённых заболеваний и здоровый лист |
| Что подаётся на вход? | Фотография одного листа, сделанная камерой или выбранная из галереи |
| Что должна вернуть система? | Класс и уверенность модели |
| Где выполнять распознавание? | На устройстве: работа без интернета, фото не покидают телефон |
| Как измерять качество? | Accuracy, precision, recall, F1 по классам и матрица ошибок на фиксированном тестовом наборе |

Основной пользовательский сценарий: выбрать или сделать фото → нажать «Определить» → получить название состояния и уверенность. Подробно: [user_scenario.md](../user_scenario.md).

Минимально рабочая версия: приложение принимает фото, запускает модель и показывает результат.

**Результат этапа:** список вопросов, сценарий и определение MVP зафиксированы (этот отчёт, `docs/user_scenario.md`).

## Этап 2. Техническая основа проекта

**Требование:** создан git-репозиторий и проект, проект собирается и запускается, пользователь может выбрать изображение, оно отображается и может быть заменено другим.

## Этап 3. Формирование и проверка датасета

**Требование:** для каждого состояния есть изображения; известны источники; проверены классы; удалены явные дубликаты; данные разделены на 3 выборки; подготовлен способ визуальной проверки.

**Что сделано.**

- Выбраны 10 классов (9 заболеваний + `healthy`). Источник данных: https://www.kaggle.com/datasets/ashishmotwani/tomato.
- Данные организованы по схеме «папка — класс», разделены на три выборки в соотношении примерно 70 / 15 / 15:

| Выборка | Изображений |
|---|---|
| train | 15 762 |
| valid | 3 373 |
| test | 3 389 |
| **Всего** | **22 524** |

- Согласованность классов проверяется автоматически: скрипт обучения прерывается, если списки классов в `train`, `valid` и `test` различаются.
- Явные дубликаты в `train` удалены скриптом `remove_duplicates.py` (сравнение по MD5-хэшу файла).

Подробнее: [dataset.md](../dataset.md).

**Результат этапа:** подготовлен датасет из 10 классов с тремя выборками.

## Этап 4. Первая модель классификации

**Требование:** модель обучена, веса сохранены, известна конфигурация обучения, программа может передать модели фото, модель возвращает класс и уверенность.

**Что сделано.**

- Скрипт `ml/train.py`: дообучение EfficientNet-B0 (последний слой заменён на 10 выходов) на GPU.
- Конфигурация обучения:

| Параметр | Значение |
|---|---|
| Размер изображения | 224 × 224 |
| Батч | 64 |
| Эпох | 10 |
| Оптимизатор | AdamW, lr = 0,0001, weight decay = 0,0001 |
| Функция потерь | CrossEntropyLoss |
| Аугментация | отражение по горизонтали, поворот ±15°, ColorJitter (0,2) |

- Лучшая модель выбирается по accuracy на `valid` и сохраняется автоматически.

**Ход обучения:**

| Эпоха | Train loss | Train acc | Valid loss | Valid acc |
|---|---|---|---|---|
| 1 | 0,7757 | 0,7795 | 0,2082 | 0,9333 |
| 2 | 0,1950 | 0,9357 | 0,1004 | 0,9701 |
| 3 | 0,1142 | 0,9625 | 0,0642 | 0,9792 |
| 4 | 0,0836 | 0,9727 | 0,0559 | 0,9825 |
| 5 | 0,0543 | 0,9832 | 0,0445 | 0,9849 |
| 6 | 0,0439 | 0,9862 | 0,0431 | 0,9861 |
| **7** | 0,0354 | 0,9881 | 0,0396 | **0,9905** |
| 8 | 0,0337 | 0,9902 | 0,0469 | 0,9884 |
| 9 | 0,0300 | 0,9902 | 0,0352 | 0,9896 |
| 10 | 0,0249 | 0,9921 | 0,0343 | 0,9902 |

Лучшей признана 7-я эпоха (valid accuracy = 0,9905). Разрыв между train и valid небольшой, valid loss к концу обучения стабилизируется на уровне 0,034–0,047: выраженного переобучения нет.

**Сохранённые артефакты:**

| Файл | Содержимое |
|---|---|
| `efficientnet_b0_best.pth` | веса лучшей эпохи, список классов, размер изображения |
| `classes.json` | названия классов в порядке выходов модели |
| `efficientnet_b0_loss.png` | график функции потерь |
| `efficientnet_b0_accuracy.png` | график точности |

Для получения класса и уверенности выход модели (10 логитов) преобразуется функцией softmax; класс с максимальной вероятностью — ответ, сама вероятность — уверенность. Подробнее: [model.md](../model.md).

**Результат этапа:** модель обучена, веса и конфигурация сохранены.

## Этап 6. Подключение модели к программе

**Требование:** пользователь может выбрать фото, нажать «Определить» и получить результат.

**Что сделано.**

- Модель переведена в формат ONNX (`ml/export_onnx.py`) и добавлена в приложение вместе с `classes.json` (`app/src/main/assets/`).
- Реализован класс `TomatoClassifier` на ONNX Runtime: предобработка изображения (RGB, 224 × 224, нормализация как при обучении), запуск модели, softmax, выбор класса и уверенности.
- Реализованы экраны анализа и результата. Выбранное фото попадает в классификатор, результат сохраняется в общем `TomatoViewModel` и отображается пользователю.

**Возникшая проблема.** Первый экспорт сохранил веса отдельным файлом (`.onnx.data`) рядом с `.onnx`. В приложение был добавлен только `.onnx`, и анализ завершался ошибкой загрузки модели. Модель переэкспортирована единым файлом `efficientnet_b0.onnx`, после чего анализ заработал.

**Результат этапа:** пользователь может выбрать или снять фото, запустить анализ и получить класс и уверенность.

## Этап 7. Проверка всех заявленных классов

**Требование:** убедиться, что система действительно работает со всем набором заболеваний; для каждого класса имеется отдельный контрольный набор изображений.

**Что сделано.** Контрольным набором для каждого класса служит его часть в тестовой выборке (в диапазоне от 191 до 454 изображений на класс). Результаты по классам:

| Индекс | Класс | Изображений | Precision | Recall | F1 |
|---|---|---|---|---|---|
| 0 | Bacterial_spot | 425 | 0,9880 | 0,9718 | 0,9798 |
| 1 | Early_blight | 336 | 0,9909 | 0,9673 | 0,9789 |
| 2 | Late_blight | 454 | 0,9956 | 0,9868 | 0,9912 |
| 3 | Leaf_Mold | 381 | 0,9870 | 0,9974 | 0,9922 |
| 4 | Septoria_leaf_spot | 433 | 0,9530 | 0,9838 | 0,9682 |
| 5 | Spider_mites Two-spotted_spider_mite | 263 | 0,9962 | 0,9962 | 0,9962 |
| 6 | Target_Spot | 275 | 0,9928 | 1,0000 | 0,9964 |
| 7 | Tomato_Yellow_Leaf_Curl_Virus | 307 | 0,9902 | 0,9902 | 0,9902 |
| 8 | Tomato_mosaic_virus | 324 | 0,9907 | 0,9846 | 0,9876 |
| 9 | healthy | 191 | 0,9948 | 1,0000 | 0,9974 |

**Выводы:**

- Все 10 классов распознаются: F1 по каждому классу не ниже 0,968, recall — не ниже 0,967.
- Самый слабый класс по precision — `Septoria_leaf_spot` (0,9530): 21 из 46 ошибок приходятся на то, что модель назвала лист септориозом. В основном это 10 листьев с бактериальной пятнистостью и 10 с ранней пятнистостью — заболевания со схожими мелкими пятнами.
- Самый слабый класс по recall — `Early_blight` (0,9673) и `Bacterial_spot` (0,9718).
- Здоровые листья не пропускаются: recall для `healthy` равен 1,0, а ложных срабатываний «здоров» всего одно (precision 0,9948).

**Результат этапа:** работа модели проверена по каждому из 10 классов.

## Выявленные проблемы и ограничения

1. **Возможное завышение метрик.** Дубликаты удалялись только по точному совпадению. Реальную точность покажет независимый набор из другого источника (этап 14).
2. **Однородность данных.** Изображения датасета получены в схожих условиях. На фото с произвольным фоном и освещением качество, вероятно, будет ниже (этапы 9–11).
3. **Нет «неизвестного» класса.** Модель всегда выбирает один из 10 классов. Для другого заболевания или не листа томата она всё равно вернёт ответ (этап 12 — порог уверенности).
4. **Путаница похожих заболеваний.** Основная ошибочная пара — бактериальная пятнистость / ранняя пятнистость / септориоз (этап 9).

## Итоги и следующие шаги

К окончанию этапа 8:

- обучена первая модель EfficientNet-B0, точность на тесте 98,64 %, macro F1 0,988;
- модель экспортирована в ONNX и встроена в Android-приложение;
- реализован основной пользовательский сценарий «фото → анализ → результат».

Далее по плану:

- этап 9 — анализ ошибок модели (пары `Bacterial_spot` / `Early_blight` / `Septoria_leaf_spot`, сложный фон, освещение);
- этап 10 — улучшенная версия модели и сравнение на том же тестовом наборе;
- этапы 11–13 — проверка качества входного фото, порог уверенности, история анализов;
- этап 14 — независимая проверка на данных из другого источника.
